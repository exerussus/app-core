## [5.0.0]

### Изменено (несовместимо)

- Отчёт аналитики — конструктор представлений. Роль события в ассете (`AnalyticsEventEntry.report`,
  `AnalyticsReportInfo`) убрана: куда событие входит, задаёт файл представлений
  `Assets/App/Settings/Editor/AnalyticsReport.json` (только редактор — в сборку не попадает, памяти рантайма не занимает).
  Роли 4.8 переносятся в него автоматически при первой загрузке редактора (пока ассет не пересохранён).
- AppCore больше не знает имён проекта: итоги прогонов, главный интервал и подписи — из каталога проекта.
  Свои итоги AppCore (`unfinished`, `interrupted`, «без итога») — служебные классы встроенного представления `app_runs`.
- События `app.focus.lost` / `app.focus.gained` больше не пишутся; на WebGL и мобильных потеря фокуса по-прежнему
  сбрасывает пакет, на ПК подписки на фокус нет вовсе.

### Добавлено

- Представления (18 типов): счётчик, интервал, воронка, разбивка, распределение, исход, дорожка таймлайна, доля,
  конверсия A → B, временной ряд, активность (DAU/WAU/MAU), удержание (когорты), прогресс, тепловая карта,
  корреляция, переходы, состояние, поток ресурса. Встроенные AppCore: `app_activity`, `app_retention`, `app_runs`
  (проект перекрывает их представлением с тем же id или скрывает).
- Привязка события к представлению: роль (факт, начало, конец, шаг, шаг пройден, значение, A, B, ось X/Y), субъект,
  мера, значение, окраска; массово — маской ключа (`Level.*`). Неклассифицированное событие — ошибка проверки
  (сборку не останавливает).
- Опции любого представления: единица счёта (события, прогоны, сессии, игроки), фильтр-выражение, вычисляемые поля,
  группировка по полям и измерениям (`@tag @result @build @platform @profile @session @run @day @week @hour @weekday
  @event @prop.<имя>`), сравнение по измерению и с прошлым периодом, цель, минимальная выборка, покрытие данных
  (незавершённые прогоны, пропуски номеров), часовой пояс, игровые или реальные часы.
- Профили экспорта (в файле представлений, общие для команды): представления, форматы, период, сырые события.
- `catalog.json` в каждой выгрузке и в report.html: события, поля, классификация, представления.
- `AppAnalytics.SetProperty(name, value)`: свойство игрока/сессии в заголовке пакета (`p.<имя>`) и событие
  `app.property`; до 16 свойств, повтор значения — без работы и аллокаций.
- report.html считается заранее в C#: в файл кладутся агрегаты и таймлайны последних прогонов (`timelineRuns`),
  а не все события.

## [4.7.1]

### Исправлено

- Аналитика, надёжность:
  - Запись события, системные события и колбэки адаптера защищены: исключение внутри модуля выключает его
    до конца запуска и не уходит в игру. Повторный вход `Flush`/доставки из адаптера (`OnFlush`, `Deliver`)
    больше не рекурсирует и не ломает обход очереди.
  - Исключения хранилища (`IAnalyticsStore`) перехватываются: дальше очередь живёт только в памяти.
  - Числа с модулем ≥ 9e12 пишутся как `null` — без неопределённого приведения `double → long` (WASM).
  - `Fail(id, NaN)` больше не оставляет пакет навсегда без повтора.
  - Имена полей в JSON экранируются.
- Аналитика, память и рост:
  - Буфер пакета выделяется лениво, на первом событии: молчащий модуль (лёгкий режим без адаптера) его не держит.
  - Экспорт в файлы по умолчанию — только в редакторе и development-сборках (в релизе папка росла бы без конца).
  - Очередь с диска подчиняется лимитам сразу при загрузке; недописанные `*.tmp` удаляются.
  - Выход из Play Mode без перезагрузки домена снимает модуль целиком; служебный объект больше не `DontSave`
    (не копится в редакторе); система PlayerLoop прошлого запуска заменяется, а не дублируется.
- Аналитика, WebGL: `Plugins/WebGL/AppAnalytics.jslib` — `visibilitychange` / `pagehide` закрывают пакет
  (WebView в фоне не шлёт blur); сброс по потере фокуса — не чаще раза в 5 с; старт без фокуса не считается уходом.
- Генерация `AppEvents`: поле не может называться `Id` / `Key`, `Raise` зовёт `Begin` по номеру события;
  переводы строк в названиях и описаниях не ломают XML-доку; несортированный каталог при загрузке редактора
  сначала записывается отсортированным.

## [4.5.0]

### Добавлено

- Именованные аргументы `{имя}` и `{имя:формат}` рядом с позиционными `{0}` — свой разбор шаблона вместо
  `string.Format`, разобранный шаблон кэшируется по тексту. Незнакомый токен (нет аргумента, не наш синтаксис)
  остаётся в строке как есть, без исключения: его дорабатывают проходы и процессор проекта.
  - Формат — только из белого списка (`N2`, `P0`, `0.0`, `#,##0`…): `{max:damage}` и
    `{max:ShieldGuardCost:a}` — токены проекта, не формат.
  - `{имя|…}` зарезервировано под окончания внутри строки (пока остаётся как есть).
  - `LocSettings.WarnUnknownTokens` — предупреждать о токене без аргумента (по умолчанию выключено).
  - Аргумент с именем-номером (`("0", x)`) подставляется в `{0}` — позиционные и именованные в одном вызове.
- Форматирование без упаковки: `Loc.Format<T0…T2>(text, ("count", 3))`, `FormatKey`, `PluralKey`,
  `LocBinder.Set<T0…T2>` / `SetPlural<T0>` — числа пишутся `TryFormat` в стековый буфер, аллоцируется только
  результат; повторный `Set` с тем же значением не стоит ничего.
- Проходы `ILocPass`: `Loc.AddPass(id, pass, stage, owner, source)`, `RemovePass`, `RemovePasses(owner)`,
  `Passes`. Стадии `Pattern` (кэшируется с переводом) и `Text` (каждый показ). `Wants` сообщает зависимости
  строки; `Loc.RefreshPass(id)` / `RefreshPass(id, dependency)` пересчитывают только зависимые строки,
  `LocBinder` пересобирает только их (`Loc.KeysRefreshed`). Проходы модов — по правилам слоёв модов.
  `Loc.Escape` — экранировать данные игры для стадии `Pattern`. История — шаг «проход изменил строку».
- Резолверы недостающих ключей: `Loc.AddResolver`, `RemoveResolver(s)`, `RefreshResolvers`, `ResolvedKeys`.
  Зовутся после фолбэков, до заглушки; промахи кэшируются. `WhereFrom` — `resolver:<id>`, история — шаг
  «значение дал резолвер».
- Ключ без `^`: `Loc.GetKey`, `TryGetKey`, `FormatKey`, `PluralKey` — общий кэш с `Get`, без склейки строк. При выключенной
  локализации возвращают сам ключ (без «^»); промах `TryGetKey` запоминается — повторный вызов без резолверов
  и аллокаций.
- Выключение на запуск: `Loc.OverrideEnabled(bool)` (до первого обращения) и `LocSettings.DisableInBatchMode`.
- AppDeck: `loc.passes` (проходы и резолверы); `loc.missing` показывает ключи, закрытые резолвером.
- EditMode-тесты локализации (`Tests/Editor`; запускаются, если пакет в `testables` манифеста).

### Изменено

- Позиционный токен с форматом вне белого списка (`{0:абв}`) больше не форматируется — остаётся в строке.
- Нехватка позиционного аргумента: недостающий токен остаётся в строке, остальное подставляется (раньше —
  весь шаблон как есть). Предупреждение — по-прежнему раз на ключ.
- Кэш переводов — по ключу без `^` (и по полной строке, один и тот же слот).

## [3.0.0]

Ломающий релиз: **минимум Unity поднят с 2020.3 до 6000.5**. На более старых редакторах пакет
не соберётся — `PanelRenderer` появился только в 6.5.

### Добавлено

- **Фрагменты** — сменное содержимое внутри вью: одна страница, разный UXML в зависимости
  от режима, конфига или выбранной мини-игры. `AppFragment : MonoBehaviour, IAppView` живёт
  дочерним объектом под своей страницей или попапом, форма та же, что у `AppPage`
  (`fragmentId`, `visualTree`, `overrideSoundLibrary`, `controller`). Точка подстановки —
  `[UxmlElement] FragmentHost` с атрибутом `host-id`; хостов во вью может быть несколько.
  - Вся обвязка достаётся даром: фрагмент — это `IAppView`, поэтому `RegisterAppView` обходит
    его кнопки и вешает звуки, сигналы и навигацию, а безопасная зона и кадр приходят от слоя,
    в котором стоит его хост. Отдельного механизма не заводилось.
  - API на вью: `ShowFragment(id, hostId = null)`, `HideFragment(hostId = null)`,
    `GetShownFragment(hostId = null)`. Хост берётся из аргумента, иначе из настроек фрагмента,
    иначе — единственный хост вью.
  - `FragmentId` — форма `PageId`/`PopupId`: FNV-1a 64, `None` при пустой строке, редакторный
    реестр имён для читаемого `ToString` и лова коллизий.
  - `unmountOnHide` (по умолчанию выключен) — сносить вёрстку при скрытии вместо переключения
    `display`. Под тяжёлые фрагменты: память освобождается, но каждый показ идёт через
    `Instantiate` заново. У таких фрагментов `AppFragmentController.Initialize()` вызывается
    на КАЖДОМ монтировании — `Root` новый, контроллер обязан перепривязаться. У обычных,
    как и у страниц, один раз.
  - Чего фрагменту не достаётся: `back__action-hook` и настройки курсора. Их разбирает
    `NavigatorService` по событию монтирования страницы — «назад» это свойство экрана,
    а не его внутреннего состояния.
  - Переключать фрагменты одного хоста должен один владелец: `Show` ждёт `OnDeactivate`
    прежнего, и два параллельных вызова переплетутся.

- `AppPopup.AppRunner` — попап теперь получает ссылку на раннер так же, как страница
  (нужна фрагментам для регистрации манипуляторов).

### Изменено

- **Вёрстка вью разделена на два дерева.** `AppPage`, `AppPopup`, `AppScreen` и `LoadingScreen`
  принимают `fullTree` (во всю полосу кадра — фон, арт, диммер) и `safeTree` (внутри безопасной
  зоны — интерактив, текст). Любое из двух можно не задавать, оба сразу — нельзя.
  - Одним отступом это не описывалось: фон обязан доходить до выреза, а текст и кнопки — нет.
    С единым вжатым контейнером получалось либо одно, либо другое.
  - Сборкой занимается общий `ViewRoot`: корень во всю полосу плюс слои `__full` и `__safe`
    внутри. Порядок добавления и есть порядок отрисовки — полноэкранное под безопасным.
  - `contentRoot` теперь вжимается **только полем кадра**; безопасную зону получает слой
    `__safe` каждого вью — по реестру, который наполняется при монтировании. Проход по нему
    идёт только при реальном изменении экрана.
  - **`IAppView.Root` сменил тип** с `TemplateContainer` на `VisualElement`: корень стал
    обёрткой, а деревьев внутри может быть два. Поиск по нему видит оба слоя, поэтому хуки,
    кнопки и хосты фрагментов находятся одним проходом независимо от слоя.
  - `AppScreen.BuildFallback()` разделён на `BuildFallbackBackdrop()` (диммер → полноэкранный
    слой) и `BuildFallbackContent()` (текст и кнопки → безопасный). Fallback строится целиком
    и только когда не задано ни одного дерева.
  - Фрагментам сплит не нужен: хост может стоять в любом слое, и фрагмент наследует поведение
    своего хоста.

- Обрезка кадра переехала на **общий контейнер** `contentRoot`, внутри
  которого живут все три слоя. Страницы, попапы и скрины растянуты на 100% и попадают в полосу
  без единого действия со своей стороны.
  - Убраны: `SafeAreaLayout` (математика переехала в `ScreenMetrics`) и свойства `SafeArea`
    у `AppPage`, `AppPopup`, `AppScreen`, `LoadingScreen`. Соглашение «элемент с именем
    `safeArea` в UXML» больше не действует — такие элементы становятся обычными контейнерами;
    безопасную зону задаёт слот `safeTree`, а не имя элемента.
  - `AppScreen.BuildSafeAreaBox()` → `BuildContentBox()`: центрирование осталось, безопасная
    зона к нему отношения не имеет.
  - Отступы кладутся в границы (`left`/`right`/`top`/`bottom`), а не в `padding` — и у
    `contentRoot`, и у слоя `__safe`. Padding здесь не работает: слои спозиционированы абсолютно,
    а у абсолютных детей точка отсчёта — padding box родителя, внутри которого отступ и лежит,
    так что элемент с `left: 0` встал бы по внутренней границе рамки, а не отступа.

- **Обрезка кадра в референсную пропорцию** (`frameToReferenceAspect`, включена по умолчанию).
  Когда окно шире, чем `referenceResolution` панели, содержимое вжимается в центральную полосу,
  а по бокам появляются чёрные поля. Пропорция берётся из самого `PanelSettings` — второго
  источника правды нет и рассинхронить нечего. Настройки: `frameMinShare`, `frameBarColor`.
  - **Второй камеры-подложки не требуется.** Поля закрашивает UI: панель App — screen-space
    overlay, она рендерится на весь экран независимо от `camera.rect`, поэтому два элемента
    поверх всего гарантированно записывают эти пиксели каждый кадр. Полагаться на то, что
    «закрасили один раз и осталось», нельзя: буфер ротируется, а в WebGL drawing buffer
    по умолчанию вообще не сохраняется между кадрами.
  - `ScreenFrameCamera` — **необязательный** компонент, сужающий `camera.rect` до полосы.
    Без него картинка уже корректна (поля перекрывают лишнее), он лишь экономит филл.
    Своего опроса `Screen` не ведёт — сравнивает версию метрик.
  - Полоса получает не только референсную пропорцию, но и референсный **размер**: на время игры
    `referenceResolution` расширяется в `1/share` раз. При `ScreenMatchMode.MatchWidthOrHeight`
    масштаб панели — взвешенная смесь ширины и высоты, и без этого полоса меряла бы себя
    в меньшем числе логических точек, отчего фиксированные px в вёрстке становились крупнее
    относительно кадра. После расширения масштаб равен `H / refH` при любом match, и полоса
    выходит ровно `refW × refH`.
  - Правка идёт по **рантайм-копии** `PanelSettings`, ассет на диске не трогается. Правки
    ScriptableObject-ассета Unity не откатывает при выходе из Play (в отличие от правок сцены),
    так что один краш — и в репозиторий уехало бы разрешение, посчитанное под чьё-то окно.
    Копия создаётся в `Awake` до регистрации UI-колбэка и уничтожается в `OnDestroy`
    с возвратом исходной ссылки рендереру.

- `ScreenMetrics` — единственное место, читающее `Screen`. Считает долю кадра и отступы
  безопасной зоны, отдаёт `Version`. Опрос — один на кадр из `AppRunner.Update`: несколько
  сравнений и выход, без аллокаций и без единой записи в стиль. Запись происходит только
  при реальном изменении экрана, ориентации, размера панели или правила кадра.
  Безопасная зона считается относительно **полосы кадра**, а не всего экрана: при обрезке вырез
  физически оказывается в чёрных полях, и отступ под него не нужен. При `share == 1` формула
  вырождается в прежнюю.

- `AppRunner` переведён с `UIDocument` на `PanelRenderer`. В 6.5 `UIDocument` объявлен obsolete:
  добавить его на новый GameObject в редакторе уже нельзя. `PanelRenderer` — нативный `Renderer`,
  рендерит сам (без скрытых companion-компонентов), сохраняет контент в памяти при disable
  и лучше дружит с World Space UI.
  - `[RequireComponent(typeof(UIDocument))]` → `[RequireComponent(typeof(PanelRenderer))]`.
  - `Awake` разрезан. У `PanelRenderer` нет синхронного `rootVisualElement`: корень приходит
    колбэком. Поэтому `Awake` теперь готовит всё, что не требует корня, и последней строкой
    регистрирует `RegisterUIReloadCallback` — строго после ранних `return` по невалидной
    конфигурации, чтобы бут не стартовал на них. Построение слоёв и `TransitionTo(CoveringScreen)`
    переехали в `OnUIReload`; отписка — в `OnDestroy`.
  - `SetupUiLayers()` → `SetupUiLayers(VisualElement root)`; `GetComponent<UIDocument>()` и
    `.rootVisualElement` убраны, корень приходит аргументом. `_root` как проба панели для
    safe area работает как раньше.
  - Повторные `OnUIReload` (OnEnable, LiveReload вёрстки) игнорируются: слои строятся и бут
    стартует ровно один раз — поведение 1:1 с прежним `UIDocument`-путём. Как следствие,
    LiveReload вёрстки в Play не подхватывается, как и до перехода.

### Миграция

1. Обновить редактор до 6.5 **до** обновления пакета — иначе проект не соберётся.
2. На объекте с `AppRunner` снять `UI Document` и добавить `Panel Renderer`, перенеся
   Panel Settings, Source Asset и Sort Order. В 6.5 у инспектора `UIDocument` есть кнопка
   апгрейда — быстрее, чем вручную.
3. Проверить сортировку: у `PanelRenderer` она идёт через унаследованный `Renderer.sortingOrder`
   и sorting layer, а не через собственное поле `UIDocument.sortingOrder`. В коде пакета это
   поле не использовалось, но если на нём что-то завязано в сцене — перепроверить после свопа.
4. Вёрстка: элементы `<VisualElement name="safeArea">` больше ничего не значат. Удалять
   не обязательно — они станут обычными контейнерами, — но отступы им никто не раздаёт.
5. Разложить вёрстку по двум слотам: фон и всё, что должно доходить до выреза — в `fullTree`,
   интерактив и текст — в `safeTree`. Старый одиночный `visualTree` больше не поле инспектора,
   ссылку придётся переназначить.
6. Наследникам `AppScreen` — заменить `BuildFallback()` на пару `BuildFallbackBackdrop()` /
   `BuildFallbackContent()`.
7. Если код где-то объявлял `TemplateContainer` под `IAppView.Root` — сменить на `VisualElement`.
8. Обрезка кадра включена по умолчанию. Если она не нужна — снять `frameToReferenceAspect`
   на `AppRunner`.

  ассета вёрстки; теперь источником становится id вью. В UI Toolkit Debugger дерево панели
  читается тем же ключом, которым вью адресуется в коде (`PageId`/`PopupId`), и имя не
  разъезжается, если uxml переименован или одна вёрстка переиспользована несколькими вью.
  На поиск и стили не влияет: `Q<T>` в ядре идёт по `mainContainer`, `safeArea` и
  `*__action-hook`, USS-селекторов `#<id>` в проекте нет.

- Скрин, построенный кодом (`BuildFallback`, когда `visualTree` не задан), получает имя типа
  вместо общего `screen-dimmer` — иначе `LoadingScreen`/`ErrorScreen`/`CriticalScreen`
  неразличимы в дереве `screensLayer` в UI Toolkit Debugger. Скрины с вёрсткой не тронуты:
  им имя даёт `Instantiate()` по имени ассета. На поиск и стили не влияет — по этому имени
  никто не ищет, USS-селекторов `#screen-dimmer` в проекте нет.

### Исправлено

- Обёртка страницы блокировала world-space ввод. `AppPage.Mount` создавал `Root`
  (`TemplateContainer`) с `flexGrow = 1` и дефолтным `PickingMode.Position` внутри
  полноэкранного `pagesLayer`. Пока страница активна, `panel.Pick()` в любой точке возвращал
  эту обёртку, событие указателя считалось обработанным screen-space панелью App и до
  world-space `UIDocument` не доходило. Слои (`_screensLayer`/`_pagesLayer`/`_popupsLayer`)
  были прикрыты `PickingMode.Ignore`, обёртка — нет. Теперь `Root.pickingMode = Ignore`:
  из пика исключается только сам элемент, дети пикаются как раньше.
  `AppPopup` не тронут — попап перехватывает ввод намеренно (модальность).

## [2.1.0]

### Добавлено

- `prewarmPages` — прогрев вёрстки всех страниц на старте. По умолчанию **выключен**:
  страница инстанцирует свой UXML при первом переходе на неё. Прогрев выполняется после
  инициализации сервисов, поэтому событие о монтировании получают все страницы.

### Исправлено

- **`OnPageMounted` не вызывался никогда.** Все страницы монтировались в `InitializingCore`,
  поэтому в навигации `Mount` всегда возвращал `false`, а сервисы подписывались на событие
  уже после этого. Следствие: `NavigatorService` не регистрировал ни back-хуки, ни настройки
  курсора — аппаратная кнопка «назад» и `cursor-lock`/`cursor-unlock` не работали вообще.
- **Кнопка «назад» не видела попапы.** Аппаратный back уводил страницу под открытым попапом,
  оставляя попап висеть. Семантика «назад» теперь одна на оба входа (аппаратная кнопка и
  кнопка в вёрстке): верхний попап → хук страницы → стек переходов.
- **`Initialize()` контроллера вызывался без `Root`.** У попапов — всегда (они монтируются
  лениво, а `Initialize` шёл на старте), у страниц — стал бы так же при ленивом монтировании.
  Теперь `Initialize` вызывается один раз сразу после монтирования, когда уже есть и
  зависимости, и вёрстка. Страницы и попапы ведут себя одинаково.
- **Контроллеры попапов не получали зависимости.** Инъекция шла в сам `AppPopup`, но не в его
  контроллер. Теперь инъецируются и вью, и контроллер — для страниц и попапов одинаково.
- **Дубликат uss-класса в `NavigationSettings` ронял старт.** `Add` бросал исключение вопреки
  комментарию про «last write wins»; заменено на присваивание по индексатору.
- **Дублирующиеся id страниц/попапов** давали нечитаемое «An item with the same key has already
  been added». Теперь ошибка называет id и оба конфликтующих объекта.

### Производительность

- Обход `NavigationLink.LinksPages`/`LinksPopups` больше не боксит энумератор: словари
  отдаются конкретным типом, а не через `IReadOnlyDictionary`. Это горячий путь — обход идёт
  на каждую кнопку каждой вью.
- `NavigationLink.Initialize` обходит `Entries` по индексу вместо `foreach` по `IReadOnlyList`.
- Диспатчер главного потока сливает очередь в переиспользуемый буфер вместо `ToArray()`
  на каждом кадре с работой.
- Кадровый путь `Update` проверен целиком и не аллоцирует: все три тика выходят по раннему 
  возврату, сервисы обходятся `foreach` по массиву.

## [2.0.1]

Только исправления найденных багов, структура не менялась.

### Исправлено

- **Попапы не получали манипуляторы.** `AppPopup` не был `IAppView` и никогда не проходил
  через `RegisterAppView`, поэтому внутри попапов не работали ни звуки UI, ни навигация
  по uss-классам. Теперь попап регистрируется при первом монтировании — это и есть его
  первая активация. Заодно у попапа появилось своё поле `overrideSoundLibrary`,
  а мёртвое поле `_registered` удалено.
- **Навигация зависела от библиотеки звуков.** Весь проход по кнопкам в `RegisterAppView`
  стоял под `if (soundLibrary != null)`, хотя в том же цикле строятся навигационные
  манипуляторы: без назначенной `UISoundLibrary` молча переставали работать переходы
  по классам. Решение «есть ли звук» теперь принимает `PageSoundService` внутри себя.
- **`OverrideSoundLibrary` ничего не переопределял.** Поле читалось в `RegisterAppView`
  и использовалось только как проверка на null, в сервис не передавалось.
  Теперь `PageSoundService` берёт библиотеку вью, а общую использует как запасную.
- **`PayloadBuilder.End()` не отпускал пейлоад.** Поле не обнулялось, поэтому следующая
  кнопка получала из `CreatePayload()` тот же самый пейлоад и перезаписывала уже
  проставленную цель навигации. Скоуп теперь закрывается на каждой кнопке, а невостребованный
  пейлоад освобождается.
- **Экран загрузки зависал при `timeScale = 0`.** `FadeTo` крутился на `Time.deltaTime`;
  переведён на `Time.unscaledDeltaTime`.
- Убран отладочный вывод из рантайма: `SoundClickManipulator` логировал создание на каждую
  кнопку каждой страницы, `AppPage`/`AppPopup` — на каждую загруженную вью, `UISignal` —
  на старте.
